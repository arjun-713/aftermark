# Working interface

The shell uses the Framed sheet direction (seed 896759026): neutral navigation and one white working sheet, IBM Plex Sans, IBM Plex Mono for IDs, and semantic color on decisions. The product's main visual is its evidence comparison. No customer, accuracy or growth figures are fabricated; overview totals derive from stored rows.

Overview answers which outcomes need attention. Runs filters agent, version, environment, quality and start date with cursor-based loading. Run detail separates execution, processing, quality and verification, with a claim beside the expected result and timestamped observations. History preserves previous policy hashes and revisions.

The review inbox supports J/K navigation, explicit assignment and version-checked decisions. Conflicts refresh the record while keeping the note for correction. A review always displays its original frozen context, with a notice when the current run has advanced. Disagreement creates a disputed review without changing the original assessment. The phone shows the queue and evidence one view at a time.

Policies save immutable drafts and require activation. Preview uses frozen observations without network requests. Connections show disconnected/configuration states; API key secrets appear once in a dialog and are never persisted in browser storage. Workspace/project selection is the only application preference stored locally; authentication uses HTTP-only cookies.

Loading rows, empty frames, permission denial, expired data, provider disconnection and retryable errors use shared states. Unknown values retain explicit labels. Focus outlines and dialogs support keyboard access; reduced-motion preferences suppress motion. Next.js production pages were inspected at 1440, 834 and 390 pixels. The login design inspection's desktop empty-space warning is intentional for a single-purpose sign-in form.
