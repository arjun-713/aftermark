# Implementation and release evidence

The release plan is the product contract. A local capability and a production release gate are tracked separately. No external sandbox, human calibration, load target, restore target, pilot result, or payment approval is implied by a green local test.

## Phase checkpoints

1. Foundation: Next.js/Fastify monorepo, runtime contracts, SQL migrations, Supabase authentication adapter, isolated local identities, scoped key management, RLS. Local gate passed: 4 contract tests, 5 authenticated API/database isolation tests, TypeScript check, production Next.js build, and Playwright login-to-workspace smoke. Dependency audit: zero findings after removing the vulnerable static documentation dependency. Supabase live authentication remains a deployment gate.
2. Ingestion: native atomic API, gzip limits, Drizzle/pg-boss transactional job creation, revisioned run search/detail, pinned OTLP HTTP JSON mapping, bounded TypeScript/Python SDKs and integration examples. Local gate passed: duplicate idempotency, conflict rollback, redaction, API/queue restart recovery, decompression limits, revoked keys, scoped identity; SDK delivery/failure-isolation tests in both languages. Worker crash/retry behavior is exercised with the evaluation worker in phase 3. Live framework/provider compatibility is not asserted by these examples.
3. Evaluation: frozen revisions, deterministic property checks and completeness validation, typed Jev adapter, immutable policy versions and previews, quota reservations, review creation, per-run worker locks, and calibration sealing/scoring tools. Local gate passed: 26 unit cases and 13 integration cases, including a process killed at the semantic request boundary and recovery without a repeated request or charge. A 400-case human-labelled corpus, live Jev validation and detector release precision remain external release gates; semantic evaluation defaults off and uncalibrated semantic findings cannot block.
4. Verification: read-only GitHub App and HubSpot OAuth flows, browser-bound one-time state, Singapore KMS envelope adapter, encrypted credential refresh, provider-host restrictions, bounded observations, signed customer receipts, and late-evidence revisions. Local protocol and signature tests cover redaction, permissions, unknown responses, replay, conflicting receipts and OAuth state rejection. Real GitHub/HubSpot sandbox records and live KMS IAM validation remain release gates; no fixture result is claimed as a live provider observation.
5. Review product: responsive Next.js working interface, real project metrics, filtered runs, claim/outcome/observation inspection, timeline and history, frozen review context, optimistic claims/decisions, disagreement states, immutable policy editing/preview, onboarding, connection health and scoped API key management. Local gate passed: 31 unit cases, 18 API/database cases, production build, and three Playwright onboarding/inspection/review flows at desktop/tablet/phone widths. Rendered screenshots inspected with IBM Plex fonts loaded, no browser errors or horizontal overflow. Alerts and the remaining commerce/regression screens are integrated in later phases. Labeled sample traces are optional (`npm run db:samples`) and use development fixture receipts, never fabricated live provider checks.
6. Regression: immutable dataset versions from resolved human reviews, separate calibration/regression manifests, explicit completion/failure/escalation behavior, frozen replay, pinned candidate comparisons, standalone CLI with JSON/JUnit/readable output and 0/1/2 exit codes, SDK packaging, and a GitHub Actions example. Local gate passed: 17 regression unit cases, 11 isolated API/CLI/database cases, standalone CLI and SDK builds/package smoke, and the full onboarding→evidence→review→dataset→comparison browser flow at desktop/tablet/phone widths. Required unknowns block by default; uncalibrated semantics remain for review. Rendering inspected after integration. Archive-reader integration follows in phase8.
7. Commerce: pending.
8. Operations: pending.

## Design decisions

Working screens use the Framed sheet direction (seed 896759026), with IBM Plex Sans and IBM Plex Mono fixed by the brief. The product's signature is claim → expected outcome → observation, with provenance and uncertainty visible together. Metrics derive from stored runs. Development examples will be identified as samples.
